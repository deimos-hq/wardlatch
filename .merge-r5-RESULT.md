## The two P1 misses, which are the findings

**Miss 1 — an unpredicted conflict.** Merge #4 (`fix/r5-audit`) conflicted on
`.github/workflows/ci.yml` as well as `test/fix-macos.check.sh`. I predicted only the latter. The ci.yml
conflict was the more serious of the two: both sides pinned a different SHA-256 for `fix/fix-macos.sh`,
and **neither matched the merged file**, which hashes
`072f60803f68e418b67c1ffdce2c28f196500745664e79a431506a16be5e1d1f`. Three round-5 commits
(`ccaa63c`, `b749850`, `fb4001a`) genuinely change the script, so both pins were stale the instant the
merge completed. `test/digest-chain.sh` caught all five inconsistencies, and its own seven-mutant
self-test passed 8 of 8 — including the mutant where `shasum` prints nothing and the check must fail
closed rather than compare two empty strings.

**Miss 2 — a predicted conflict that did not happen.** Merge #5 (`docs/r5-truth-a`) did **not** conflict
on `expect_cases`. Cause: `docs/r5-truth-a` **descends from `38c0c71`**, where the value was already 102,
so its 102 is inherited and the change was one-sided. My prediction's topology treated truth-a as
branching from `99a7f7d` alone. It did conflict on `CHANGELOG.md`, which I had not predicted at all.

**CORRECTED 2026-11-02 after seat 4 of the panel.** I originally wrote that both misses had one cause,
the incomplete lineage model. That is true of Miss 2 only, and the corrective check I recorded would not
have caught Miss 1.

- **Miss 2 is lineage.** `38c0c71` is an ancestor of `docs/r5-truth-a`, so its `expect_cases` change was
  one-sided. Deriving the lineage set with `git merge-base --is-ancestor` over every pair fixes this.
- **Miss 1 is SCOPE, not lineage.** At merge #4 both sides had changed `.github/workflows/ci.yml` since
  the merge base `99a7f7d` — two `git diff --name-only` calls show it. I predicted conflicts by reasoning
  about ONE LINE of ONE FILE instead of intersecting the changed-file sets of the two sides. No amount of
  lineage work would have surfaced it.

So the check to add is both: intersect the changed-FILE sets to find where conflicts can occur at all,
then use lineage to decide which of those actually will.

**P6 was vacuous and I graded it MET.** Its premise — "all seven refs already touch `lib/binaries.mjs`" —
came from grepping for files *containing* Go-related strings, not files *changed*. **No merged commit
touches that file: zero.** Of P6's six files the merge changes only `CHANGELOG.md`. The check could not
have produced a different answer, which is the definition of an instrument that proves nothing. It is
regraded NOT TESTED, and the Go coupling remains unverified by this merge because the merge does not
touch it. The only branch that does is `feat/brotli-r5`, which is excluded.
